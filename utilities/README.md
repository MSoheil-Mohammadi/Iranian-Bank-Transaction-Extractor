# ابزارها (Utilities)

مجموعه‌ای کوچک از ابزارهای مستقل و قابل استفادهٔ مجدد برای
**نرمال‌سازی متن، پاک‌سازی داده‌ها و اعتبارسنجی شناسه‌های بانکی**.

این پکیج با پایتون خالص پیاده‌سازی شده و در حال حاضر **هیچ وابستگی
خارجی** ندارد.

---

## ساختار پکیج

```text
utilities/
├── text/
│   ├── digits.py
│   ├── letters.py
│   ├── normalize.py
│   ├── punctuation.py
│   ├── whitespace.py
│   └── __init__.py
│
├── iban.py
├── luhn.py
├── README.md
└── __init__.py
```

پکیج از دو بخش مستقل تشکیل شده:

| بخش       | نوع     | کاربرد                                      |
| --------- | ------- | ------------------------------------------- |
| `text/`   | زیرپکیج | نرمال‌سازی متن فارسی/عربی                   |
| `luhn.py` | ماژول   | اعتبارسنجی شماره کارت بانکی (Luhn / Mod 10) |
| `iban.py` | ماژول   | اعتبارسنجی شبا (Mod 97 / ISO 13616)         |

## ۱. زیرپکیج `text` — نرمال‌سازی متن

### این زیرپکیج چه کاری انجام می‌دهد؟

مجموعه‌ای از توابع برای یکسان‌سازی متن فارسی و عربی پیش از پردازش.
هدف اصلی، **آماده‌سازی متن برای تطبیق Regex و استخراج اطلاعات
بانکی** است.

مشکل‌های رایج متن‌های واقعی که این زیرپکیج حل می‌کند:

| مشکل                          | ماژول         | مثال                           |
| ----------------------------- | ------------- | ------------------------------ |
| ارقام فارسی/عربی              | `digits`      | «۱۲۳» → «123»                  |
| حذف کاراکترهای غیرعددی        | `digits`      | «۴۱۱۱-۱۱۱۱» → «41111111»       |
| حذف کاراکترهای غیرحرف‌وعددی   | `digits`      | «IR۸۲-۰۵۴۰» → «IR820540»       |
| حروف عربی جایگزین             | `letters`     | «ي» و «ك» → «ی» و «ک»          |
| نیم‌فاصله و کاراکترهای نامرئی | `whitespace`  | «سلام\u200cجهان» → «سلامجهان»  |
| فاصله‌های یونیکد عجیب         | `whitespace`  | No-Break Space → فاصلهٔ معمولی |
| علائم نگارشی فارسی            | `punctuation` | «،» «؛» «؟» → «,» «;» «?»      |

### چرا نرمال‌سازی لازم است؟

در متن تراکنش‌های واقعی، کاربران یا سیستم‌های بانکی از ارقام و
حروف متفاوتی استفاده می‌کنند. مثلاً ممکن است یک تراکنش با ارقام
فارسی «۶۰۳۷...» و تراکنش دیگر با ارقام ASCII «6037...» ثبت شده
باشد. اگر قبل از استخراج نرمال‌سازی نکنیم، Regexها فقط یکی از
حالت‌ها را تشخیص می‌دهند و نتیجه ناقص می‌شود.

همچنین نیم‌فاصله (ZWNJ) که در فارسی بسیار رایج است، می‌تواند وسط
یک عدد یا بین حروف قرار بگیرد و تطبیق الگو را خراب کند.

### توابع موجود

| تابع                           | ماژول         | کاربرد                                         |
| ------------------------------ | ------------- | ---------------------------------------------- |
| `normalize_digits(text)`       | `digits`      | تبدیل ارقام فارسی/عربی به ASCII                |
| `strip_non_digits(text)`       | `digits`      | حذف کاراکترهای غیرعددی (با تبدیل خودکار ارقام) |
| `strip_non_alphanumeric(text)` | `digits`      | حذف کاراکترهای غیرحرف‌وعددی ASCII              |
| `normalize_letters(text)`      | `letters`     | یکسان‌سازی حروف عربی (ي، ى، ك)                 |
| `normalize_whitespace(text)`   | `whitespace`  | پاک‌سازی فاصله‌ها و کاراکترهای نامرئی          |
| `normalize_punctuation(text)`  | `punctuation` | یکسان‌سازی علائم نگارشی                        |
| `normalize_text(value)`        | `normalize`   | تابع جامع که همهٔ مراحل بالا را ترکیب می‌کند   |

### رابط عمومی (API)

```python
from utilities.text import normalize_text

normalize_text("کارت: ۶۰۳۷-۹۹۱۲-۳۴۵۶-۷۸۹۰")
# 'کارت: 6037-9912-3456-7890'

normalize_text("شبا:‌ IR12 3456 ...")
# 'شبا: IR12 3456 ...'  (نیم‌فاصله حذف شده)

normalize_text("كارت‌ من  ي  دارم")
# 'کارت من ی دارم'

normalize_text(None)
# ''
```

### استفاده از توابع مستقل

اگر فقط یکی از مراحل را لازم داری، می‌توانی تابع مربوطه را جداگانه
صدا بزنی:

```python
from utilities.text import (
    normalize_digits,
    normalize_letters,
    normalize_whitespace,
    normalize_punctuation,
    strip_non_digits,
    strip_non_alphanumeric,
)

normalize_digits("۱۲۳")               # '123'
normalize_letters("كتاب")             # 'کتاب'
normalize_whitespace("a\u200cb")      # 'ab'
normalize_punctuation("سلام،")        # 'سلام,'

# این دو تابع خودشان ارقام فارسی/عربی را هم به ASCII تبدیل می‌کنند
strip_non_digits("۴۱۱۱-۱۱۱۱")         # '41111111'
strip_non_alphanumeric("IR۸۲-۰۵۴۰")   # 'IR820540'
```

### ترتیب مراحل در `normalize_text`

تابع `normalize_text` مراحل را به این ترتیب انجام می‌دهد:

۱. مدیریت مقادیر خالی (`None`، `NaN`).
۲. نرمال‌سازی یونیکد با `NFKC`.
۳. تبدیل ارقام فارسی/عربی به ASCII.
۴. یکسان‌سازی حروف عربی (`ي`، `ى`، `ك`).
۵. پاک‌سازی فاصله‌ها و کاراکترهای نامرئی.
۶. یکسان‌سازی علائم نگارشی.

### محدودیت‌ها

- `NFKC` برخی کاراکترها را به شکل‌های عجیب تبدیل می‌کند (مثلاً «ﷲ» به
  «الله»). اگر این رفتار را نمی‌خواهی، `normalize.py` را تغییر بده.
- **نیم‌فاصله (ZWNJ) به‌طور کامل حذف می‌شود.** این رفتار برای
  استخراج شماره‌های بانکی درست است، ولی اگر روزی خواستی متن فارسی
  را نمایش بدهی، باید این رفتار را تغییر دهی.
- `strip_non_alphanumeric` فقط **حروف انگلیسی ASCII و ارقام ASCII**
  را نگه می‌دارد. سایر کاراکترها (از جمله حروف فارسی) حذف می‌شوند.
- برای زبان‌های دیگر (عربی، اردو) باید جدول تبدیل حروف را گسترش دهی.

## ۲. ماژول `luhn.py` — الگوریتم Luhn (Mod 10)

### این ماژول چه کاری انجام می‌دهد؟

الگوریتم Luhn یک فرمول چک‌سام ساده است که برای اعتبارسنجی انواع
شماره‌های شناسایی استفاده می‌شود؛ از جمله:

- شماره کارت‌های بانکی (ویزا، مسترکارت و ...)
- شماره IMEI گوشی‌های موبایل
- شماره‌های بیمه و برخی شناسه‌های ملی

### الگوریتم چگونه کار می‌کند؟

۱. از سمت راست شروع می‌کند و هر رقم دوم را دو برابر می‌کند.
۲. اگر حاصل دو برابر شدن بزرگ‌تر از ۹ شد، ۹ واحد از آن کم می‌کند.
۳. همهٔ ارقام را با هم جمع می‌زند.
۴. اگر مجموع بر ۱۰ بخش‌پذیر بود، شماره را معتبر اعلام می‌کند.

### چرا از این الگوریتم استفاده می‌شود؟

شماره کارت‌ها طولانی هستند (معمولاً ۱۶ رقم) و به‌راحتی اشتباه تایپ
می‌شوند. الگوریتم Luhn بیشتر خطاهای رایج انسانی را تشخیص می‌دهد:

- یک رقم اشتباه تایپ‌شده
- جابه‌جایی دو رقم مجاور

در این پروژه، پس از استخراج یک عدد ۱۶ رقمی از متن تراکنش با Regex،
الگوریتم Luhn به‌عنوان **فیلتر** عمل می‌کند تا اعداد ۱۶ رقمی
تصادفی (شماره پیگیری، کد فاکتور و ...) را حذف کند و فقط اعدادی که
شبیه شماره کارت واقعی هستند باقی بمانند.

### توابع موجود

| تابع                  | ورودی       | خروجی           | توضیح                                    |
| --------------------- | ----------- | --------------- | ---------------------------------------- |
| `clean_card(value)`   | رشتهٔ خام   | رشتهٔ فقط ارقام | حذف کاراکترهای غیرعددی (بدون اعتبارسنجی) |
| `luhn_check(card)`    | رشتهٔ ارقام | `bool`          | اعتبارسنجی خالص Luhn                     |
| `is_valid_card(card)` | رشتهٔ خام   | `bool`          | ترکیب پاک‌سازی + Luhn + بررسی ۱۶ رقم     |

### رابط عمومی (API)

```python
from utilities.luhn import luhn_check, clean_card, is_valid_card

clean_card("4111-1111-1111-1111")     # '4111111111111111'
luhn_check("4111111111111111")        # True
luhn_check("4111111111111112")        # False
luhn_check("")                        # False (محافظ)
is_valid_card("4111 1111 1111 1111")  # True
```

### الگوی Regex

```python
CARD_PATTERN = re.compile(r"\b[1-9]\d{3}[\s-]?\d{4}[\s-]?\d{4}[\s-]?\d{4}\b")
```

این الگو در ماژول تعریف شده تا در `main.py` برای استخراج کاندید
شماره کارت از متن تراکنش استفاده شود.

### محدودیت‌ها

- Luhn یک مکانیزم امنیتی نیست؛ فقط خطاهای ساختاری را تشخیص می‌دهد.
- عبور از Luhn به این معنا نیست که کارت وجود دارد، فعال است یا موجودی دارد.
- در موارد بسیار نادر، ممکن است برخی کارت‌های واقعی از Luhn عبور نکنند.

## ۳. ماژول `iban.py` — الگوریتم Mod 97 (ISO 13616)

### این ماژول چه کاری انجام می‌دهد؟

الگوریتم Mod 97، استاندارد بین‌المللی **ISO 13616** را برای
اعتبارسنجی شماره‌های شبای ایرانی پیاده‌سازی می‌کند. شبای ایرانی
**۲۶ کاراکتر** دارد و همیشه با `IR` شروع می‌شود.

### ساختار شبای ایرانی

```text
IR  XX  YYY  NNNNNNNNNNNNNNNNNNN
│   │   │    │
│   │   │    └── شماره حساب (۱۹ رقم)
│   │   └────── کد بانک (۳ رقم)
│   └────────── رقم کنترلی (۲ رقم)
└────────────── کد کشور (IR)

جمع: ۲ + ۲ + ۳ + ۱۹ = ۲۶ کاراکتر
```

### الگوریتم چگونه کار می‌کند؟

۱. چهار کاراکتر اول شبا (یعنی `IR` به‌همراه دو رقم کنترلی) را به
انتهای رشته منتقل می‌کند.
۲. حروف باقی‌مانده را با معادل عددی دو رقمی‌شان جایگزین می‌کند.
چون در شبای ایرانی تنها حروف موجود `I` و `R` هستند، این مرحله
به سادگی به تبدیل زیر خلاصه می‌شود:

- `I` → ۱۸
- `R` → ۲۷
  ۳. رشتهٔ حاصل را به‌عنوان یک عدد صحیح بسیار بزرگ در نظر می‌گیرد.
  ۴. باقی‌ماندهٔ تقسیم این عدد بر ۹۷ را محاسبه می‌کند.
  ۵. اگر باقی‌مانده برابر **۱** شد، شبا معتبر است.

### چرا از این الگوریتم استفاده می‌شود؟

شباها هم حرف دارند و هم رقم و طولانی هستند؛ به همین دلیل در برابر
خطاهای تایپی آسیب‌پذیرند. Mod 97 این خطاها را تشخیص می‌دهد:

- هر کاراکتر اشتباه تایپ‌شده
- بیشتر جابه‌جایی‌های دو کاراکتر مجاور
- بسیاری از خطاهای رایج دیگر در ورودی

در این پروژه، Mod 97 به‌عنوان **فیلتر** پس از استخراج شبا نامزد از
متن تراکنش عمل می‌کند تا فقط شباهای معتبر از نظر ساختاری باقی بمانند.

### توابع موجود

| تابع                  | ورودی       | خروجی                         | توضیح                       |
| --------------------- | ----------- | ----------------------------- | --------------------------- |
| `clean_iban(value)`   | رشتهٔ خام   | رشتهٔ uppercase بدون جداکننده | حذف جداکننده‌ها + uppercase |
| `iban_check(iban)`    | شبا پاک‌شده | `bool`                        | اعتبارسنجی خالص Mod 97      |
| `is_valid_iban(iban)` | رشتهٔ خام   | `bool`                        | ترکیب پاک‌سازی + Mod 97     |

### رابط عمومی (API)

```python
from utilities.iban import iban_check, clean_iban, is_valid_iban

clean_iban("IR82 0540 1026 8002 0817 9090 02")
# 'IR820540102680020817909002'

iban_check("IR820540102680020817909002")  # True
iban_check("IR820540102680020817909003")  # False
is_valid_iban("IR82-0540-1026-8002-0817-9090-02")  # True
```

### الگوی Regex

```python
IBAN_PATTERN = re.compile(r"IR(?:[\s\-*/]*\d){24}", re.IGNORECASE)
```

این الگو در ماژول تعریف شده تا در `main.py` برای استخراج کاندید
شبا از متن تراکنش استفاده شود.

### محدودیت‌ها

- Mod 97 یک چک‌سام است، نه یک مکانیزم امنیتی.
- شبای معتبر به این معنا نیست که حساب واقعاً وجود دارد یا فعال است.
- این ماژول **فقط شبای ایرانی** را پشتیبانی می‌کند. برای کشورهای
  دیگر باید مقدار `IRAN_IBAN_LENGTH`، پیشوند کشور و دیکشنری
  `_IRAN_IBAN_LETTER_VALUES` را تغییر دهی.

## تفاوت دو الگوریتم اعتبارسنجی

| ویژگی      | Luhn                           | Mod 97                          |
| ---------- | ------------------------------ | ------------------------------- |
| کاربرد     | کارت بانکی، IMEI               | شماره شبا (IBAN)                |
| طول        | معمولاً ۱۶ رقم                 | ۲۶ کاراکتر برای ایران           |
| عملیات     | دو برابر کردن هر رقم دوم و جمع | تبدیل حروف به عدد و تقسیم بر ۹۷ |
| شرط اعتبار | مجموع % ۱۰ == ۰                | باقی‌مانده % ۹۷ == ۱            |
| استاندارد  | ISO/IEC 7812                   | ISO 13616                       |
| پیچیدگی    | ساده                           | کمی پیچیده‌تر (به‌خاطر حروف)    |

## نصب و استفاده

هیچ وابستگی خارجی نیاز نیست. کافی است ماژول‌ها را import کنی:

```python
# اعتبارسنجی کارت بانکی
from utilities.luhn import luhn_check, clean_card, is_valid_card

# اعتبارسنجی شبا
from utilities.iban import iban_check, clean_iban, is_valid_iban

# نرمال‌سازی متن
from utilities.text import normalize_text
```

اگر می‌خواهی توابع را مستقیماً از خود پکیج `utilities` بگیری:

```python
from utilities import (
    luhn_check,
    clean_card,
    is_valid_card,
    iban_check,
    clean_iban,
    is_valid_iban,
)
```

> **نکته:** زیرپکیج `text` به‌صورت عمدی از `utilities/__init__.py`
> export نشده تا جداسازی مسئولیت‌ها حفظ شود. برای دسترسی به آن
> باید مسیر کامل را بنویسی: `from utilities.text import normalize_text`.

## طراحی و مسئولیت‌ها

مسئولیت‌ها بین ماژول‌ها به این شکل تقسیم شده:

```text
                    utilities
                        │
            ┌───────────┴───────────┐
            │                       │
          text                    banking
            │                       │
     ┌──────┼──────┐          ┌─────┴─────┐
     │      │      │          │           │
  digits letters ...       luhn         iban
                              │           │
                          clean_card   clean_iban
                              │           │
                          luhn_check  iban_check
                              │           │
                        is_valid_card is_valid_iban
```

هر ماژول **فقط یک کار** انجام می‌دهد:

- `text/*`: نرمال‌سازی و پاک‌سازی متن.
- `luhn.py`: پاک‌سازی و اعتبارسنجی کارت بانکی.
- `iban.py`: پاک‌سازی و اعتبارسنجی شبا.

این جداسازی باعث می‌شود:

- هر بخش را بتوان مستقل تست کرد.
- تغییرات در یک بخش روی بخش‌های دیگر اثر نگذارد.
- ماژول‌ها را بتوان در پروژه‌های دیگر هم استفاده کرد.
